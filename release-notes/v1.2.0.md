# TerritorySweeper 1.2.0

基于 **LeviLamina (LL3)** + **PLand** + **DebugShape** + **iListenAttentively** 的基岩版领地分层分块清扫原生 C++ 插件。

本次版本主题是 **多任务并行管理**：同一领地可以同时运行多个清扫任务、挂起多张待支付账单，
并配套「领地清扫任务列表」统一入口、BossBar 公平轮换、每任务彩色线框与账单红色线框；
同时修复了一批交互可达性、显示与提示问题，并把构建/发版链路升级到 **LLVM 23 + LeviLamina 26.51.9 + GitHub Actions**。

---

## 🚀 核心新特性

### 1. 同一领地多任务 + 领地清扫任务列表
- 新增配置 `allow_multi_task_per_land`（默认 `true`）：一个领地可同时存在多个清扫任务，仍受全服上限（`global_task_limit`）与玩家上限（`player_task_limit`）约束；
- **木棍路由按条目数分流**：
  - 领地内任务 + 账单**合计 1 个** → 直接打开对应面板（与旧版完全一致，无额外菜单）；
  - **合计 ≥ 2 个** → 打开「领地清扫任务列表」，逐条进入管理；
- **列表条目两行展示**，一眼看清状态与进度：
  ```
  任务#12 · 进行中        │  任务#13 · 已暂停
  进度 52％ · 第 4/10 层  │  释放倒计时 265s · 进度 12％
  ```
- 列表内置 **「刷新」** 按钮：重新解析脚下领地后按最新数据重开，进度/倒计时/条目变化即时可见；
- `/ts list` 调整为「全服清扫任务总览」，领地内请用木棍打开领地任务列表。

### 2. 同一领地多张挂起账单（数据库 schema v4）
- `bills` 表由「`land_id` 单主键」改为「`bill_id` 自增主键 + `land_id` 索引」，同一领地可挂多张账单，各自独立支付 / 关闭；
- **自动迁移**：启动时检测旧结构 → `VACUUM INTO` 生成一致性备份 → 事务内 `RENAME / CREATE / INSERT SELECT / DROP`，任一步失败整体回滚并告警（任务与退款不受影响，下次启动重试）；
- 账单操作全部改为按 `billId`，杜绝「支付一张误删同领地其它账单」；
- 修复：账单余额不足跳转费用页后支付成功仍残留原账单；同一计划重复「挂起账单」会堆叠两份的问题。

### 3. BossBar 公平轮换 + 每任务独立彩色线框
- **轮换规则重做**：只有**剩余释放时间 ≤ 60 秒**的临界暂停任务才被钉住常显；只要还有运行中的任务，就至少保留 1 个槽位参与轮换，其余槽位在全部任务间按 `bossbar_rotate_seconds` 滑窗轮换；
  - 修复「2 个暂停任务占满 2 条 BossBar，运行中任务永远不显示」；
  - 任务数 ≤ `bossbar_max_bars` 时不轮换，行为与旧版一致。
- **每个任务一条独立线框**：`task-frame-<id>`，颜色按任务 ID 取青/绿/橙/紫/粉/黄，任务结束自动消失；
  - 修复「多任务时只有第一个任务有线框、其余共用同一 key 互相覆盖」。

### 4. 账单线框 + 按钮配色分级
- **账单区域线框**：`bill-frame-<id>`，固定红色，挂起后**立即出现**、支付或关闭后**立即消失**；只有账单、没有任务的玩家同样会刷新（此前这类玩家根本不进入看板刷新循环）；
- **按钮配色分级**（浅灰按钮上全部可读，禁用白/灰/浅色）：
  | 用途 | 颜色 |
  | :--- | :--- |
  | 主操作：立即支付 / 继续 / 新建 / 刷新 | 深绿 |
  | 次操作：挂起账单 / 暂停任务 | 深蓝 |
  | 危险：停止任务 / 关闭账单 | 红色 |
  | 中性：关闭 / 返回 / 保留 | 黑色 |
  | 列表状态词：进行中 / 已暂停·待支付 | 深绿 / 金色 |

### 5. 构建与发版工程化
- 工具链升级到 **LeviLamina 26.51.9 + clang-cl 23（LLVM 23）**，clang 19 在 `MinecraftCommands.h` 上的编译错误彻底解决；
- 预编译 LeviLamina SDK 通过 `xmake-repo-extra` 分发，CI 不再需要每次编译上游本体；
- iListenAttentively 导入库改为构建期由入库 `.def` 自动生成（`ILA.def` + `xmake.lua on_load`），并修正 `/DELAYLOAD` 开关从未生效的问题（`add_shflags`）；
- 新增 GitHub Actions：
  - `build.yml`：push `main` / PR 自动编译校验并上传 artifact；
  - `release.yml`：推送 `v*` tag 自动构建、校验版本注入、打包 `TerritorySweeper-<版本>.zip` 并创建 Release。

## 🐛 修复清单

| 问题 | 根因 |
| :--- | :--- |
| 「`player_task_limit` 形同虚设，同一领地无法建第二个任务」 | `checkCreateAllowed()` 的「一领地一任务」判定排在玩家上限之前，玩家上限永远轮不到 |
| 重启后同领地的第 2、3 个任务消失 | `db::loadTasks()` 按 `land_id` 去重 |
| `/ts new` 选点时，木棍直接弹出上一个任务的管理面板 | 木棍交互中「任务」分支排在「选点」分支之前 |
| 领地已有任务时，挂起账单无法再通过木棍支付 | 任务分支命中即 `return`，账单分支永远不可达 |
| `/ts ok`、`/ts posN` 可把坐标写进别的领地 | 未校验选区所属领地 |
| 界面把计费档位名 `9*9` 当成选区尺寸 | `plan.levelname` 是档位名，尺寸应从 `min/max` 坐标算 |
| 两个暂停任务占满轮播，运行中的任务永远不显示 | 暂停任务按数量整体钉住，`free = cap - pinned` 直接为 0 |
| 多任务时只有第一个任务有线框 | 线框只跟随「主任务」，且共用一个 key |
| 终止/退款消息没有任务编号，且一次操作发两条 | 消息未带 ID，表单与指令各发一条 |

## ⚙️ 配置变更（`config_version` 4 → 5）

升级时会自动备份旧配置为 `config.jsonc.bak-<时间戳>` 并按新模板重写，**用户既有配置值完整保留**。

| 配置项 | 类型 | 默认值 | 说明 |
| :--- | :--- | :--- | :--- |
| `allow_multi_task_per_land` | bool | `true` | 是否允许同一领地同时存在多个任务（关闭恢复旧限制） |
| `bossbar_max_bars` | int | `2` | 同一玩家同时可见的 BossBar 条数上限（超出轮换） |
| `bossbar_rotate_seconds` | int | `5` | BossBar 轮换间隔（秒） |

---

## 🗄️ 数据库变更（schema v3 → v4）

- `bills` 表重建为 `bill_id INTEGER PRIMARY KEY AUTOINCREMENT` + `land_id` 索引；
- 迁移前自动执行 `VACUUM INTO '<db>.bak-<时间戳>-schema-v4.db'` 生成一致性备份；
- 迁移在单个事务中完成，失败自动回滚（账单功能降级，任务与退款正常），下次启动重试；
- 旧库中的账单完整保留（迁移为 `bill_id` 主键的一行）。

---

## ⬆️ 升级步骤

1. 停服，将 `TerritorySweeper.dll` 与 `manifest.json` 覆盖到 `plugins/TerritorySweeper/`；
2. 起服：日志会输出 `数据库已升级到 schema v4（bills 支持同一领地多张账单）` 与配置迁移提示；
3. 首次启动后检查 `plugins/TerritorySweeper/data/` 与 `config/` 下的 `.bak-<时间戳>` 备份文件；
4. 需要多任务时把 `player_task_limit` 调到 2 以上（默认仍为 1）。
