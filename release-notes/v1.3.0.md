# TerritorySweeper 1.3.0

基于 **LeviLamina (LL3)** + **PLand** + **DebugShape** + **iListenAttentively** 的基岩版领地分层分块清扫原生 C++ 插件。

本次版本主题是 **跟随 LeviLamina 26.60 正式版**：mod 安装目录统一到 `mods/`、构建 SDK 抬到 **26.60.8**、
三方依赖同步到 PLand 0.26 / ILA 0.18 / DebugShape 0.12。

> 本版**不改变任何游戏内功能、配置结构与数据库结构**（`config_version` 仍为 5、schema 仍为 4），
> 是一次纯粹的兼容性与工程版本；升级本身不涉及配置迁移或数据迁移。

---

## 🎯 主要变更

### 1. 适配 LeviLamina 26.60：插件目录 `plugins/` → `mods/`

自 LL 26.60 起，服务端 mod 根目录由 `plugins/` 统一改为 `mods/`，两套目录**不可混用**：

| 项目 | 26.51 及更早 | 26.60 起（本版） |
| :--- | :--- | :--- |
| 插件目录 | `plugins/TerritorySweeper/` | `mods/TerritorySweeper/` |
| 配置 | `plugins/TerritorySweeper/config/config.jsonc` | `mods/TerritorySweeper/config/config.jsonc` |
| 数据 | `plugins/TerritorySweeper/data/territorysweeper.db` | `mods/TerritorySweeper/data/territorysweeper.db` |

同时修正了 `tooth.json` 的资产声明：此前 `assets` 是**空数组**，等于 lip 不会安装任何文件、只能手工复制 DLL；
本版改为 zip 资产 + `placements`，**通过 lip 安装时文件会正确落到 `mods/TerritorySweeper`**。

### 2. MCAPI 逐函数开放：审计结论为「0 个符号需要申请」

26.60 出于安全考虑不再整类开放 MCAPI：`mc/_HeaderOutputPredefine.h` 新增 `MCNAPI`
（`[[deprecated]]` + 未开放，需到 [mcapi-requests](https://github.com/LiteLDev/mcapi-requests) 逐条申请）。

本版对全部外部符号做了逐个宏核对：

- 成品导入分布：`LeviLamina.dll` 62 个、`bedrock_runtime.dll` 16 个、`iListenAttentively.dll` 1 个；
- 16 个 `bedrock_runtime.dll` 导入（Scoreboard、MinecraftPackets、CommandOutput、UUID、Actor、BlockSource 等）
  逐个核对宏标记，**全部为 `MCAPI` 或 `MCFOLD`，无 `MCNAPI`**；
- 结论：**无需向 mcapi-requests 提交任何申请**。

过程中唯一命中的受限 API 已改为等价可用写法（`src/Visual.cpp`，BossBar 名称赋值）：

```cpp
// 旧：拷贝赋值在 26.60 中受限
pkt->mName = Bedrock::Safety::RedactableString{*title};
// 新：走 MCAPI 的 operator=(std::string&&)
pkt->mName = std::string{*title};
```

另外**移除了 `-Wno-deprecated-declarations`**：该开关原本会把 MCNAPI 的申请提示一并吞掉。
今后误用未开放 API 会在编译期直接报
`warning: '…' is deprecated: This API is not available… [-Wdeprecated-declarations]`。

### 3. 构建与 SDK 分发

- 预编译 SDK 升到 **26.60.8**，以 `sdk-v26.60.8` pre-release 分发（`include/` + `lib/LeviLamina.lib`）；
- 新增 `tools/build-sdk-from-release.ps1`：官方 release 只提供 `LeviLamina.dll`（不含 include/lib），
  该脚本可从上游 tag 反向合成完整 SDK —— sparse clone `src/` + `src-server/` 两层 overlay 出头文件树，
  再由 DLL 的 961 个具名导出生成导入库，最后打成 zip 并打印 sha256；
- 包定义支持 `TS_LL_SDK_LOCAL=<zip 所在目录>` 本地回退，适配新 LL 版本时无需先上传 Release 即可构建；
- 依赖清单随 LL 26.60.8 补齐 `parallel-hashmap v2.0.0`，`bedrockdata` 升到 `v26.60.6-server.16`。

## ⚙️ 配置与数据库

- `config_version` 保持 **5**，无新增/删除/重命名配置项；
- 数据库 schema 保持 **4**，无结构变更；
- 因此升级时**不会**触发配置备份重写与数据库迁移。

---

## ⬆️ 升级步骤

1. 停服，并把服务端本体升级到 **LeviLamina 26.60.x**；
2. 把原 `plugins/TerritorySweeper/` **整个目录移动到** `mods/TerritorySweeper/`
   （务必连同 `config/` 与 `data/` 一起搬，否则会丢配置与任务数据）；
3. 用本版 `TerritorySweeper.dll` + `manifest.json` 覆盖 `mods/TerritorySweeper/` 下的旧文件；
4. 起服，确认启动日志中的依赖探针全部通过（PLand / DebugShape / LegacyMoney / iListenAttentively）；
5. 使用 lip 的用户可直接按 `tooth.json` 安装，文件会自动落到 `mods/TerritorySweeper`。

> 回退提示：本版构建依赖 LL 26.60 的头文件与运行时，**不能**在 26.51 及更早的服务端上运行。
